# v0.4.3 — Background update checks and update notifications

The plugin now checks for updates on its own schedule instead of only while the Quick Access Menu is open, and tells you when a new release is available. This release also adds a guided desktop installer for people who would rather not use Decky's Developer Mode.

## Update Checking

- **Checks now run in the background.** Previously every update check was triggered by the Updates section mounting, which only happens while the QAM panel is open — close the panel and update checking stopped entirely. Device logs showed this clearly: every `check_start` was preceded by `qam_content_mounted`, and plugin loads where the panel was never opened produced no checks at all. A poller now runs for the lifetime of the plugin, checking 30 seconds after load and every 6 hours thereafter. This makes the "Automatically check for updates" toggle description accurate for the first time. (#0695dab, #6371f72)

- **A toast announces an available update.** A newly available release raises one notification, deduplicated by release tag so it does not reappear on every plugin reload. The new **Plugin Updates** toggle under Notifications controls it, and the master **All Notifications** switch silences it along with everything else. (#56be3ac, #6b17873, #0fbb4e0)

- **Automatic checks no longer bypass the 24-hour cache.** An effect dependency caused automatic checks to run with `force=true` after hydration settled, skipping the backend's 24-hour cache and hitting the GitHub releases API on every occurrence. Automatic checks now honor the cache; only the manual "Check now" button forces a fetch. (#5a9d312)

Background checks are deliberately cheap: they always request an unforced check, so the backend's 24-hour cache stays in control and a real GitHub fetch happens at most once per day regardless of how often the poller ticks.

## Installation

- **Added a guided desktop installer.** `SDH-Ludusavi Installer Bundle.zip` in the repository root installs or updates the plugin from SteamOS Desktop Mode without enabling Decky Developer Mode. It resolves the newest release, enforces HTTPS with redirect re-validation, verifies the asset SHA-256 before installing, and replaces an existing install atomically with rollback on failure. Extract it onto the Desktop and double-click the launcher. (#f0a11d4, #163f4b3)

## Security

- Cleared **GHSA-mh99-v99m-4gvg** (high-severity, `brace-expansion`) by removing the vulnerable dependency chains rather than suppressing the advisory. The package was reachable only through two dev-only build tools, and `minimatch@3` can never accept the patched `brace-expansion@5` API — so overriding `brace-expansion` directly was impossible. Overriding the intermediates instead (`@rollup/plugin-commonjs` 26→29, `rollup-plugin-delete` 2.2→3.0.2) drops both chains: `brace-expansion` no longer resolves at all. `pnpm audit` now reports no known vulnerabilities with no advisories ignored. As with v0.4.2, this was build-environment exposure only and never shipped in the plugin ZIP. (#a69fd1d)

- Pinned `postcss` to 8.5.18 for **GHSA-r28c-9q8g-f849**. (#363ff3e)
